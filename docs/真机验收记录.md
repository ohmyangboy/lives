## 当前自动验证边界

- React/TypeScript production build、项目模型测试、Swift 编译和模板裁剪测试已自动完成。
- Tauri App 已完成 ad-hoc 签名与 bundle 校验，内嵌 Swift sidecar 已通过独立启动和请求响应测试；`.app` 与 `.dmg` 均已生成。
- 2026-07-19 使用三段真实视频完成了编码、封面提取和 Live Photo 元数据写入；生成的照片与配对视频已通过 `PHLivePhoto.request` 校验。
- 首次真实运行停在 75% 的原因是 sidecar 主线程被同步标准输入循环占用，PhotoKit 校验回调无法执行。现已改为异步输入，并为校验增加取消、30 秒超时和单次回调保护；取消任务的临时目录已验证清理。
- 输出位置支持“照片”与指定文件夹：文件夹模式会生成同名 JPG 封面和 MOV 动态资源，自动避免覆盖，并可在 Finder 中定位。
- 照片权限在渲染前请求；2026-07-19 已验证“隐私与安全性 → 照片”出现 LiveCollage 且可开启“完全访问”。拒绝后提供“打开系统设置”“改存到文件夹”和“已授权，重新尝试”三条恢复路径。
- 2026-07-19 已在获得授权后完成一次真实 Live Photo 保存，主流程顺利跨过 2% 的授权阶段并显示“你的 Live Photo 已就绪”。
- 照片辅助程序使用独立 bundle identity、照片图库 entitlement 与 `LSUIElement`，不在 Dock 中显示；仅主 App 出现在运行应用列表，开发版和正式版同时运行造成的双图标问题已定位。
- 已生成并嵌入 LiveCollage 正式图标；App bundle 中存在 `CFBundleIconFile = icon.icns`，图标资源和应用签名均通过校验。
- 自动化不会向真实“照片”图库写入测试资产；PhotoKit、iCloud 和小红书链路必须按上表人工确认。
