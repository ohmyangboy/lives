## 2. 下一阶段优先级

### P0：发布质量与可信分发

1. 完成真机验收矩阵，修复阻断性导出、Live 属性、封面或交互问题。
2. 申请 Apple Developer Program；配置 Developer ID、Hardened Runtime、公证与 stapling。
3. 建设官网分发：Cloudflare Pages + R2 提供版本化 DMG、下载页、更新说明与安装指引。
4. 未获得正式签名前，不向普通用户宣传“自动更新”；保持 DMG 手动更新。

### P1：正式更新与稳定性

1. 在签名与公证就绪后接入 Tauri Updater：更新签名密钥、HTTPS `latest.json`、应用内检查/下载/重启安装、失败回退到官网。
2. 用 GitHub Actions 建立发布流水线：构建、签名、公证、产物校验、上传 R2、最后发布更新清单。
3. 为导入大文件夹添加性能观察：封面首次显示时间、滚动帧率、内存峰值、导入失败率。

### P2：基于真实用户反馈再决定

- Intel/Universal 包。
- 显式项目文件与继续编辑。
- 模板扩展、批量导出、素材搜索/筛选。

## 3. 发布验收矩阵

### 自动检查

- [ ] `npm run build`
- [ ] `npm test`
- [ ] `swift test --package-path native/LivePhotoService`
- [ ] `npm run tauri:build`
- [ ] `codesign --verify --deep --strict --verbose=2 Lives.app`
- [ ] 正式发布阶段：公证和 stapling 校验通过

### 核心功能

| 场景 | 通过标准 |
| --- | --- |
| 直接导入多段视频 | 默认项目显示全部素材，封面可见，原文件未复制 |
| 导入文件夹 | 创建正确 Tab，视频全部归类，关闭 Tab 行为正确 |
| 同一素材放入多格 | 每格可设置不同 3 秒片段和裁剪，导出结果互不串位 |
| 8 个模板 × 横竖屏比例 | 预览格局与最终 JPG/MOV 边界、比例一致，无拉伸或黑边异常 |
| 关键帧 | 仅把手可拖动；播放结束停在设定帧；导出封面与设定帧一致 |
| 清除拼贴 | 拼贴格与临时编辑状态重置；素材、项目 Tab、比例偏好仍存在 |
| 1080P/720P | 输出尺寸与选择一致；素材不足时不允许伪 1080P 放大 |
| 声音 | 静音、指定、混合三种输出符合选择，混音无爆音/不同步 |

### Live Photo 与平台链路

| 场景 | 通过标准 |
| --- | --- |
| 保存到“照片” | 仅产生一个 Live Photo 资产，Mac“照片”显示 LIVE 且可播放 |
| 权限拒绝 | 清楚解释仅添加照片用途；可进入设置或改导出文件夹 |
| iCloud → iPhone | 同步后仍为 Live Photo，长按可播放 |
| 目标第三方 App | 实际选择、发布、回看流程保持动态效果（按目标平台补充记录） |
| 保存到文件夹 | JPG 与 MOV 成对同名、可在 Finder 定位、不覆盖已有文件 |

## 4. 发布门槛

只有同时满足以下条件才可从“内部测试”变为“公开发布”：

1. 自动检查全部通过。
2. 至少完成单画面、上下二拼、左右二拼、经典三拼和复杂三拼各一轮真实导出。
3. Mac“照片”及至少一台 iPhone 的 Live Photo 链路通过。
4. 素材封面、大文件夹导入、清除拼贴、关键帧拖动均经人工回归。
5. 获得 Developer ID、完成公证；官网提供版本化下载和明确的隐私/安装说明。
